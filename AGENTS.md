# 仓库工作约定

## 工作流程与 Git

1. 开始前检查 Git 状态；文件修改在功能或文档分支完成。
2. 按下表读取相关约定，限定本次修改范围。
3. 每阶段验证通过后，仅暂存本次任务改动，审阅暂存差异并自动提交；只读任务不提交。
4. 最终以 `git merge --ff-only` 合并至 `main`，不在 `main` 创建提交。交付说明改动、实际检查和人工验收项。

分支分叉时先定位原因，保留提交与用户改动；不以硬重置、清理文件或强推绕过。

## 命令优先级

- 查找文件优先用 `rg --files`，搜索文本优先用 `rg`；命令以 [package.json](package.json) 为准，复用 pnpm 脚本。
- 代码默认 lint；类型变化用 check 替代 lint。其余检查仅按触发条件追加，不逐级执行。

| 触发条件                 | 检查方式                                                                |
| ------------------------ | ----------------------------------------------------------------------- |
| 仅修改文档               | 审阅差异、核对链接；不运行代码检查或构建                                |
| 常规代码改动             | `pnpm lint`，包含模块边界检查                                           |
| 类型接口变化或类型错误   | `pnpm check`，包含 lint                                                 |
| 行为变化或具体故障需验证 | 相关测试文件或最小复现，见 [局部验证入口](doc/workflow.md#局部验证入口) |
| 构建变化或需交付产物     | `pnpm build`                                                            |
| 部署配置变化需核验       | `pnpm deploy:dry-run`，仅本地验证                                       |

## 安全边界

- **用户文件**：保留原始 `DESIGN.md`，不覆盖、回滚或删除用户已有改动。
- **模块职责**：目录、公开入口与依赖方向遵循架构文档。
- **公开配置**：浏览器和静态产物仅接收公开配置；Waline 数据库与管理凭据仅存独立服务端，不进入源码、产物、日志或 Git。示例使用占位值。
- **远端操作**：push 和远端部署须有用户明确指令；本地提交与合并不代表发布授权。

## 验证限制与人工验收

- 全局测试仅在跨模块影响且局部验证不足时执行，先说明原因。
- 已通过的检查仅在相关改动或失败需复核时重跑；不为流程或覆盖率增加全面测试。
- 布局、响应式、字体、间距与视觉效果由用户人工验收；不编写或执行自动截图、视觉回归或浏览器布局扫描。

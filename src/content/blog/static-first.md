这是一篇演示博客排版的示例文章。它讨论静态网站的组织方式，不代表作者已完成的工作经历。

## 内容先于交互

个人网站的大部分页面，在读者打开之前就已经确定。介绍、项目、文章正文，都可以在构建时成为 HTML。

静态输出让页面有一个清晰的起点：即使浏览器脚本还没有加载，读者也能读完内容、打开链接。

## 把职责放回各自的位置

Markdown 保存正文。内容 schema 检查字段。页面负责组合项目、文章与站点布局。搜索和评论各自管理浏览器中的交互。

```ts
const publishedPosts = posts.filter((post) => {
  return !post.draft && post.publishedAt <= today;
});
```

### 什么时候需要客户端脚本

当一个动作需要立即反馈时，例如搜索、复制代码或打开移动导航，才增加相应的脚本。

| 功能 | 执行位置 | 原因 |
| --- | --- | --- |
| 文章正文 | 构建时 | 内容在发布时已确定 |
| 站内搜索 | 浏览器 | 响应读者的查询 |
| 评论 | 外部服务 | 需要保存读者提交的数据 |

## 给下一步留下空间

静态网站并不妨碍后续增加新功能。先让边界清楚，之后才能知道新能力应该放在哪里。

> 一个功能的名字，应该能说明它负责什么。
